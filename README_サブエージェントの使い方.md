# アプリ開発用サブエージェント

このフォルダの `.claude/agents/` に置いた4つの役割定義は、**このフォルダ配下で Claude Code を起動したとき**に自動で読み込まれます。今後このフォルダの中にアプリを作っていけば、どのアプリでも同じ4役が使えます。

## 4つの役割

| 役 | 何をするか | いつ呼ぶか |
|---|---|---|
| **verifier**（検証役） | 成果物をまっさらな目で壊しにかかる。数字の再計算、元資料との突き合わせ、事実の裏取り、論理の穴 | **後戻りしにくいものを出す直前。** 価格・条文・統計データの差し替え・リリース前 |
| **researcher**（調査役） | 外部情報を調べ、裏取りできた結論と出典だけを持ち帰る | 他社価格・法令・公的統計・技術仕様を調べるとき |
| **implementer**（実装役） | 設計が固まった後の実装作業。設計判断はしない | テスト追加・一括置換・データ差し替え・定型的な機能追加 |
| **handoff-writer**（引継書役） | 引継書とINDEXを書く／更新する | 作業の区切り |

## 使い方

呼び方は3通りあります。**確実なのは2番目（@メンション）です。**

**1. 自然な文で頼む**（Claude が内容から判断して選ぶ）

```
verifier サブエージェントを使って、価格設計の叩き台を検証して
implementer サブエージェントで、課題整理表の P-03 を直して
```

**2. @メンションで名指しする（確実）**

```
@"verifier (agent)" 課題整理表の P-03 の修正を検証して
```

`@` を打つと候補が出るので、そこから選べます。**「必ずこの役に投げたい」ときはこれを使ってください。**

**3. セッションごと1つの役で起動する**

```
claude --agent verifier
```

検証だけを続けてやりたいときに。

> **補足：** 「verifier で〜して」のような短い日本語の指定でも通ることは多いですが、**確実に選ばれる保証はありません**（Claude が description を見て判断するため）。外したくない場面では2番の @メンションを使ってください。

## いつ使わないか（ここが費用対効果の分かれ目）

サブエージェントは、呼ぶたびにそれなりのトークンを使います。**些細な修正のたびに検証役を走らせるのは割に合いません。**

| 使う | 使わない |
|---|---|
| 価格・条文など、後から変えにくいもの | 変数名の変更、コメント追加 |
| 統計データの差し替え（年1回） | 表示文言の微修正 |
| リリース前の最終確認 | 動作を目で見れば分かる変更 |
| 顧客に出す資料 | 自分用のメモ |

**判断基準は「間違えたまま外に出たら困るか」**です。困るなら検証役、困らないならそのまま進める。

## なぜ検証役が効くのか

書いた本人には、自分の決めごとの記憶があります。「案Sはサポートなし」と決めた記憶があると、サポート原価を満額のせた計算式を見ても違和感が湧きません。**まっさらな状態で読む役がいて初めて見つかります。**

能力の差ではなく、**文脈を持っているかどうかの差**です。だから検証役には編集ツールを渡していません。直せてしまうと、直した本人になってしまい、検証の目が失われます。

## フォルダの場所について（重要）

**アプリを置くフォルダのパスには、日本語や記号を使わないことを強く勧めます。**

PL Analyzer で実際に踏んだ問題です。

- パスに `【企業】` が含まれていたため **Turbopack が起動できなくなった**（`byte index ... is not a char boundary; it is inside '【'`）。回避のため webpack 指定に固定したままになっています
- 日本語パスへの `cd` が、文字コードの正規化の差（NFD/NFC）で失敗することがある

**`~/apps/pl-analyzer` のような半角英数のパスなら、この2つは最初から起きません。** 資料や成果物のフォルダは日本語で構いませんが、**コードを置くフォルダだけは半角英数**にしておくと、後で悩む時間が減ります。

## 既存のアプリでも使いたいとき

このフォルダの外にあるアプリでは、`.claude/agents/` を読み込めません。方法は2つです。

1. **そのアプリのフォルダに `.claude/agents/` をコピーする**（アプリごとに独立。おすすめ）
2. **`~/.claude/agents/` に置く**（全プロジェクトで有効。ただしどのアプリでも同じ定義になる）

同梱の `.command` は、先頭の `TARGET` を書き換えるだけでどちらにも設置できます。

## 動かないときの確認

| 症状 | 原因と対処 |
|---|---|
| 名前を出しても選ばれない | **Claude Code を再起動する。** 起動後に置いたファイルは読み込まれないことがある |
| それでも選ばれない | @メンション（上記2番）で明示的に呼ぶ |
| 「zero tools」というエラーが出る | `tools:` のツール名の綴りミス。有効なのは Read / Write / Edit / Glob / Grep / Bash / WebFetch / WebSearch / NotebookEdit / TodoWrite / Skill と MCPツール |
| 別のフォルダで使えない | `.claude/agents/` は**そのフォルダで起動したときだけ**有効。全プロジェクトで使いたいなら `~/.claude/agents/` に置く |

`name` は**小文字とハイフンのみ**が使えます（`handoff-writer` は可、大文字や日本語は不可）。ファイル名と一致させておくのが無難です。

## 育て方

この4つは出発点です。**使ってみて「ここが足りない」と思ったら、`.claude/agents/*.md` を直接書き換えてください。** ただの Markdown ファイルです。

特に `implementer.md` の「既知の落とし穴」の表は、**新しく踏んだものを足していくほど価値が上がります。** 引継書に書いた落とし穴のうち、実装作業で毎回効くものは、こちらにも書いておくと事故が減ります。
